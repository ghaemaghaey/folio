# Offline Support Plan for Folio Reader

## Problem

When users lose internet access:
- **Progress sync silently fails** -- positions saved locally but never pushed to server; on next online open, server may overwrite with stale data
- **OPDS catalog is blank** -- no cached catalog data, user sees error messages
- **Uploads fail** -- no queuing, user must retry manually
- **No offline indicator** -- user doesn't know if they're online/offline

Core reading (PDF/EPUB rendering, local progress, shelf, themes) already works offline.

---

## Design: Three-Layer Offline Strategy

### Layer 1: Offline Queue (Progress + Uploads)

Queue failed sync/upload operations and replay them when connectivity returns.

**Progress sync queue:**
- When `syncProgressToServer()` fails (network error), save the pending sync to `localStorage` key `folio.pendingSyncs` as an array of `{fingerprint, position, device, timestamp}`
- On app start and on `online` event, drain the queue: POST each pending sync, remove on success
- On book open, if queue has a newer entry for that fingerprint than the server, prefer the queued entry
- Cap queue at 200 entries (FIFO eviction)

**Upload queue:**
- When upload fails with network error, save `{file.name, file.size, title, author, timestamp}` to `localStorage` key `folio.pendingUploads`
- On `online` event, retry queued uploads in order
- Show a subtle "N uploads pending" badge on the upload button

**Files to modify:**
- `desktop/frontend/dist/main.js` -- add `queueSync()`, `drainSyncQueue()`, modify `syncProgressToServer()` and `beforeunload`
- `android/app/src/main/assets/www/main.js` -- same changes

### Layer 2: OPDS Catalog Cache

Cache the last successfully loaded OPDS catalog so users can browse their library offline.

**Strategy:**
- After each successful `loadCatalogInitial()` / `loadCatalogPage()`, save the rendered entries to `localStorage` key `folio.catalogCache` as `{entries: [...], timestamp, opdsUrl}`
- On catalog load, try network first. If network fails, fall back to cached data and show a banner: "Offline -- showing cached catalog"
- Cache is keyed by OPDS URL so switching servers invalidates it
- Cap cache at 500 entries

**Files to modify:**
- `desktop/frontend/dist/main.js` -- add cache read/write in `loadCatalogInitial()` and catalog error paths
- `android/app/src/main/assets/www/main.js` -- same

### Layer 3: Offline Status Indicator

Show the user whether they're online or offline.

**UI:**
- Add a small status dot in the library header (green = online, orange = offline, pulsing when reconnecting)
- When offline, show a subtle banner at top of library: "You're offline -- changes will sync when reconnected"
- When queued syncs/uploads drain, show a toast: "Synced N items"

**Files to modify:**
- `desktop/frontend/dist/index.html` -- add status indicator element
- `desktop/frontend/dist/style.css` -- styles for indicator and banner
- `desktop/frontend/dist/main.js` -- `navigator.onLine` + `online`/`offline` event listeners
- `android/app/src/main/assets/www/index.html` -- same
- `android/app/src/main/assets/www/style.css` -- same
- `android/app/src/main/assets/www/main.js` -- same

---

## Implementation Order

1. **Offline queue for progress sync** (highest value -- prevents data loss)
2. **Offline status indicator** (quick win -- user awareness)
3. **OPDS catalog cache** (medium complexity -- improves offline experience)
4. **Upload queue** (lower priority -- uploads are less frequent)

---

## Server-Side Changes (None Required)

The server already handles:
- Duplicate progress upserts gracefully (ON CONFLICT DO UPDATE)
- Unknown fingerprints auto-create stub book rows
- No pagination needed for initial implementation (library is small)

No server changes needed -- all offline logic is client-side.

---

## Verification

1. **Progress sync queue**: Disconnect network → open book → scroll → close book → check `localStorage.getItem("folio.pendingSyncs")` has entry → reconnect → verify POST fires and queue drains
2. **OPDS cache**: Load catalog online → disconnect → reload app → verify cached catalog shows with offline banner
3. **Status indicator**: Disconnect → verify orange dot + banner → reconnect → verify green dot + sync toast
4. **Upload queue**: Disconnect → try upload → verify queued → reconnect → verify auto-retry
5. **Conflict resolution**: On Device A (offline) read to page 50 → on Device B (online) read to page 30 → reconnect A → verify A's position (50) wins because it's newer
