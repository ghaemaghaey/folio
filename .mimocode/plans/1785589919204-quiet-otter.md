# Fix: Device Picker Position Not Applied

## Bug

When selecting a device from the picker, the chosen position is not applied. The book always opens at the local device's position.

## Root Cause

In `openBookId`, when a device is chosen from the picker:
- `savedChapter` / `savedPage` are updated ✓
- But `savedScroll` is NOT reset to 0 ✗

Later, the restore logic checks `if (opts.restoreScroll > 0)` — since `savedScroll` still holds the local scroll ratio (e.g., 0.45), it's > 0, so the restore scrolls to the old position instead of jumping to the chosen chapter.

## Fix

In both EPUB and PDF picker branches, set `savedScroll = 0` when a device is chosen:

```js
if (chosen && chosen.pos) {
  savedPage = chosen.pos.p ?? savedPage;
  savedChapter = chosen.pos.c ?? savedChapter;
  savedSubPage = chosen.pos.s ?? savedSubPage;
  savedScroll = 0;  // ← ADD THIS: force chapter-based restore, not scroll-based
}
```

### Files to modify:
- `android/app/src/main/assets/www/main.js` (lines ~1567 and ~1585)
- `desktop/frontend/dist/main.js` (same logic)

## Verification

1. Read EPUB on PC to chapter 5, 50% through
2. Open same EPUB on Android → picker shows
3. Select PC → should jump to chapter 5, not stay on Android's chapter
