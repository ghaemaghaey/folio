# Fix Device Picker Not Showing

## Root Causes

### 1. `flushProgress()` never syncs to cloud (Primary)

I removed `syncProgressToServer()` from `flushProgress()` earlier to reduce server load. But this means progress ONLY reaches the server on:
- `closeReader()` (which calls `flushProgress` but doesn't sync)
- `beforeunload` (unreliable on Android, doesn't fire on book-switch)

**Result:** Device A's progress stays local. Device B never sees it. Picker never triggers.

**Fix:** Re-add `syncProgressToServer` to `flushProgress`, but debounce it to sync at most every 30 seconds (not on every scroll). This balances server load with cross-device sync.

### 2. DB migration silently keeps old schema (Secondary)

`CREATE TABLE IF NOT EXISTS` in `db.go` won't add the `device` column to an existing table. If the server was deployed before the device feature, `UpsertProgress` fails with "no such column: device".

**Fix:** Add `PRAGMA table_info` check + `ALTER TABLE ADD COLUMN` fallback in the migration.

---

## Fix 1: Periodic sync in flushProgress

### Desktop & Android `main.js`

In `flushProgress()`, after the local save, add a debounced cloud sync:

```js
// After local save, sync to cloud at most every 30 seconds
if (!state._lastCloudSync || Date.now() - state._lastCloudSync > 30000) {
  state._lastCloudSync = Date.now();
  syncProgressToServer(state.doc.fingerprint, page, chapter, sub, scroll);
}
```

This syncs at most once per 30 seconds during active reading, plus always on close (via `closeReader` → `flushProgress`).

## Fix 2: DB migration with ALTER TABLE fallback

### `server/internal/db/db.go`

After the `CREATE TABLE IF NOT EXISTS` for `reading_positions`, add:

```go
// Check if device column exists, add it if missing (migration from pre-device schema)
rows, err := db.Query("PRAGMA table_info(reading_positions)")
if err == nil {
    hasDevice := false
    for rows.Next() {
        var cid int
        var name string
        // ... scan
        if name == "device" { hasDevice = true }
    }
    rows.Close()
    if !hasDevice {
        db.Exec("ALTER TABLE reading_positions ADD COLUMN device TEXT NOT NULL DEFAULT ''")
        // Re-create primary key with device column
        // SQLite doesn't support ALTER PRIMARY KEY, so we need to recreate the table
    }
}
```

Actually, SQLite doesn't support `ALTER TABLE ... ADD COLUMN` with NOT NULL + DEFAULT on older versions, and can't change primary keys. The safest approach:

1. Check if `device` column exists via `PRAGMA table_info`
2. If not, create a new table with the correct schema
3. Copy data from old table
4. Drop old table
5. Rename new table
