# Multi-Device Sync Fix Plan

## Problem

When users have 2+ devices (multiple PCs, PCs + phones), sync breaks in several ways:
- Two PCs both report as "Desktop" → share one DB row → overwrite each other
- `beforeunload` sends beacon without auth header → 401 silently → position lost
- Device picker only compares page number → misses scroll/chapter differences
- Server does blind upsert with no timestamp guard → stale data can overwrite fresh
- Cloud sync only on close → app crash kills lose all progress

---

## Fix 1: Unique Device Identification (Critical)

**Root cause:** `getDeviceName()` returns only `"Desktop"`, `"Android"`, or `"iOS"`. Two PCs share the same name.

**Fix:** Generate a stable per-machine ID on first run, store in `localStorage`. Combine with platform for human-readable name.

### Desktop (`desktop/frontend/dist/main.js`)

Replace `getDeviceName()` (line 167-174):

```js
function getDeviceName() {
  let id = localStorage.getItem("folio.deviceId");
  if (!id) {
    id = Math.random().toString(36).slice(2, 10);
    localStorage.setItem("folio.deviceId", id);
  }
  const ua = navigator.userAgent || "";
  let platform = "Desktop";
  if (/Android/i.test(ua)) platform = "Android";
  else if (/iPhone|iPad|iPod/i.test(ua)) platform = "iOS";
  // For Desktop, append short ID so two PCs don't collide
  if (platform === "Desktop") return `Desktop-${id}`;
  return platform;
}
```

### Android (`android/app/src/main/assets/www/main.js`)

Same change — Android phones also need unique names if someone has 2 phones:

```js
function getDeviceName() {
  let id = localStorage.getItem("folio.deviceId");
  if (!id) {
    id = Math.random().toString(36).slice(2, 10);
    localStorage.setItem("folio.deviceId", id);
  }
  return `Android-${id}`;
}
```

### Device picker display

The device picker already shows `d.device` as the name. With `Desktop-a3f8k2m1` it'll show a short ID. To make it user-friendly, add a settings option later to rename devices. For now, the short random ID is sufficient to prevent collisions.

**Files:** `desktop/frontend/dist/main.js`, `android/app/src/main/assets/www/main.js`

## Fix 2: Server-Side Timestamp Guard (Critical)

**Root cause:** `UpsertProgress` does blind `ON CONFLICT DO UPDATE` — last write always wins even if it's older data.

**Fix:** Only update if the incoming `updated_at` is newer than the stored one.

### `server/internal/store/store.go`

Change `UpsertProgress` (lines 138-175):

```sql
INSERT INTO reading_positions (user_id, book_fingerprint, device, position, updated_at)
VALUES (?, ?, ?, ?, ?)
ON CONFLICT(user_id, book_fingerprint, device) DO UPDATE SET
  position = CASE
    WHEN excluded.updated_at > reading_positions.updated_at THEN excluded.position
    ELSE reading_positions.position
  END,
  updated_at = CASE
    WHEN excluded.updated_at > reading_positions.updated_at THEN excluded.updated_at
    ELSE reading_positions.updated_at
  END
```

This ensures a delayed sync from Device A (with timestamp T1) cannot overwrite a more recent sync from Device B (with timestamp T2 > T1).

**File:** `server/internal/store/store.go`

## Fix 3: Auth Header on `beforeunload` Beacon (Critical)

**Root cause:** `navigator.sendBeacon()` with a raw `Blob` doesn't send the `Authorization` header. Server returns 401. Position is lost.

**Fix:** Use `fetch()` with `keepalive: true` instead of `sendBeacon`. `fetch` with `keepalive` supports custom headers and survives page unload.

### `desktop/frontend/dist/main.js` (lines 3665-3687)

Replace `sendBeacon` with:

```js
window.addEventListener("beforeunload", () => {
  if (state.doc && isLoggedIn() && state.doc.fingerprint) {
    // ... calculate pos, device ...
    if (!navigator.onLine) {
      queueSync(state.doc.fingerprint, pos, device);
    } else {
      // fetch with keepalive survives page unload AND supports auth headers
      fetch(`${FOLIO_API_BASE}/progress`, {
        method: "POST",
        headers: {
          "Content-Type": "application/json",
          "Authorization": `Bearer ${account.token}`,
        },
        body: JSON.stringify({ fingerprint: state.doc.fingerprint, position: pos, device }),
        keepalive: true,
      }).catch(() => {
        // Queue for retry if beacon fails
        queueSync(state.doc.fingerprint, pos, device);
      });
    }
  }
});
```

Same change for Android `main.js`.

**Files:** `desktop/frontend/dist/main.js`, `android/app/src/main/assets/www/main.js`

## Fix 4: Device Picker Compares Full Position (Medium)

**Root cause:** Picker only compares `pos.p` (page number). Two devices on the same page with different scroll/chapter are treated as identical.

**Fix:** Compare a composite key of `page + chapter + subPage`.

### `desktop/frontend/dist/main.js` (line 1405)

Change:
```js
const unique = new Set(parsed.map((d) => d.pos.p));
if (parsed.length > 1 && unique.size > 1) {
```

To:
```js
const posKey = (d) => `${d.pos.p}:${d.pos.c || 0}:${d.pos.s || 0}`;
const unique = new Set(parsed.map(posKey));
if (parsed.length > 1 && unique.size > 1) {
```

Same change for Android.

**Files:** `desktop/frontend/dist/main.js`, `android/app/src/main/assets\www\main.js`

## Fix 5: Periodic Cloud Sync (Medium)

**Root cause:** Cloud sync only happens on `closeReader` and `beforeunload`. If the app crashes or is force-killed, cloud position is stale.

**Fix:** Sync to cloud on every `flushProgress` call (which already runs on scroll/position change with 250ms debounce).

### `desktop/frontend/dist/main.js`

In `flushProgress()` (around line 670), after the local save, add cloud sync:

```js
// After local save:
syncProgressToServer(state.doc.fingerprint, page, chapter, sub, scroll);
```

This was removed earlier (changed to close-only). Re-add it but with the understanding that the offline queue handles failures gracefully. The `syncProgressToServer` function already queues on failure, so this is safe.

**Files:** `desktop/frontend/dist/main.js`, `android/app/src/main/assets/www/main.js`

---

## Fix 6: Remove Duplicate Sync on Close (Low)

**Root cause:** `closeReader` calls `syncProgressToServer` and `beforeunload` also calls it. Double POST on every close.

**Fix:** Since `flushProgress` now syncs on every save, `closeReader` and `beforeunload` don't need their own sync calls. Remove them to avoid double-POST.

### `desktop/frontend/dist/main.js`

- Remove the sync block from `closeReader` (lines 1645-1658)
- Remove the `beforeunload` handler entirely (lines 3665-3687)

The periodic `flushProgress` sync + offline queue is sufficient.

Same for Android.

**Files:** `desktop/frontend/dist/main.js`, `android/app/src/main/assets/www/main.js`

---

## Implementation Order

1. **Fix 1: Unique device IDs** — prevents the most common collision
2. **Fix 2: Server timestamp guard** — prevents stale overwrites
3. **Fix 3: Auth on beacon** — fixes the silent 401 on page close
4. **Fix 5: Periodic cloud sync** — ensures progress is always current
5. **Fix 6: Remove duplicate sync** — cleanup
6. **Fix 4: Full position comparison** — better device picker UX
